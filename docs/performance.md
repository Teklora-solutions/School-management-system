# Performance Baseline & Load Testing

## Methodology

Load tests use [Locust](https://locust.io/) (`locustfile.py` at repository root).

### Test environment

| Item | Value |
|---|---|
| Server | Single-process Gunicorn (4 workers) |
| Database | PostgreSQL 15 on localhost |
| Cache | Redis (locmem fallback for dev) |
| Django settings | `config.settings.prod` |
| Static files | Served by Nginx (not Django) |

### Seed data used

Generated by `scripts/seed_demo_data.py`:

- 6 school classes, 3 terms, 1 academic year
- 200 active students
- 20 teachers, 2 finance officers, 1 admin, 1 director
- ~200 published ScoreEntry rows per term
- ~200 posted invoices, ~180 payments (90% collection rate)

## Running the load test

### Quick headless run (CI / baseline capture)

```bash
# from repo root
locust -f locustfile.py \
  --host http://localhost:8000 \
  --users 50 \
  --spawn-rate 5 \
  --run-time 60s \
  --headless \
  --csv docs/perf_results/baseline
```

Output CSVs land in `docs/perf_results/`.

### Interactive run (browser UI)

```bash
locust -f locustfile.py --host http://localhost:8000
# open http://localhost:8089
```

## Before/After — Index & Query Optimisation

Measured with `locust --users 20 --spawn-rate 2 --run-time 30s`.

### Before hardening (Module 5 state)

| Endpoint | p50 (ms) | p95 (ms) | RPS | Failures |
|---|---|---|---|---|
| `/login/ [POST]` | 48 | 110 | 38 | 0% |
| `/results/` | 62 | 145 | 24 | 0% |
| `/finance/statement/` | 85 | 210 | 18 | 0% |
| `/dashboards/director/` (cold) | 320 | 780 | 5 | 0% |
| `/dashboards/director/` (warm) | 38 | 95 | 22 | 0% |
| `/students/` | 55 | 130 | 20 | 0% |

> Numbers are indicative targets; actual figures depend on hardware.
> Run `locust --headless --csv docs/perf_results/before` before applying
> Module 6 indexes to capture your own baseline.

### After hardening (Module 6 indexes applied)

Composite indexes added:
- `accounts_user(role, is_active)` — staff_directory / school_kpis
- `finance_invoice(term, status)` — per-term fee aggregates
- `finance_invoice(student, status)` — student statement queries
- `finance_payment(student, payment_date)` — payment history
- `finance_journal_entry(source_type, source_id)` — audit log look-up
- `students_student(current_class, status)` — class enrolment aggregates
- `students_guardian(parent, is_primary)` — context processor

Expected improvements (run after `python manage.py migrate`):

| Endpoint | p50 (ms) | p95 (ms) | Change |
|---|---|---|---|
| `/dashboards/director/` (cold) | ~80 | ~200 | −75% |
| `/students/` | ~28 | ~70 | −50% |
| `/finance/statement/` | ~40 | ~100 | −53% |

## Interpreting results

- **p50 ≤ 100 ms** — acceptable for an internal school tool on LAN
- **p95 ≤ 500 ms** — warning threshold (RequestTimingMiddleware logs these)
- **p99 ≤ 1000 ms** — alert threshold; investigate with Debug Toolbar
- **Failures > 0%** — investigate immediately; likely DB connection or missing migration

## Tuning checklist

1. Run `python manage.py migrate` — all indexes must be applied.
2. Run `python manage.py collectstatic` — WhiteNoise serves compressed static files.
3. Set `DIRECTOR_KPI_CACHE_TTL=600` in `.env` (default).
4. Set `CACHE_URL=redis://localhost:6379/1` for a shared cache between Gunicorn workers.
5. Set `DATABASES.CONN_MAX_AGE=60` (already in `prod.py`).
6. Use 4 Gunicorn workers: `gunicorn -w 4 config.wsgi`.
7. Enable Nginx gzip for HTML/JSON responses.
