{# ── How it works ─────────────────────────────────────────────────────────── #}

How the assistant works

The assistant only answers from documents you approve. It cannot invent fees, dates or policies. If it cannot find a good answer it says so plainly and directs the person to the school office.

Every question goes through this pipeline in order. No step can be skipped:

1
Safeguarding screen
Every message is checked against a mandatory safeguarding rule set before anything else. A hit never reaches the AI — the person gets a kind, brief reply with the school's safeguarding contact and emergency numbers. An alert is immediately sent to admin and director. This cannot be switched off.
2
Rate limit & budget check
The kill switch, per-user daily limit and monthly KSh budget are checked. If any is exceeded the assistant declines with a plain message — no provider call is made and nothing is charged.
3
Knowledge retrieval (scope filter first)
The question is matched against your approved knowledge documents using hybrid search (keyword + vector). Only documents the asker is allowed to see are searched — a visitor never retrieves staff-only content. If nothing relevant is found, the assistant refuses without calling the AI provider.
4
Live data tools (signed-in users only)
For signed-in parents, students, teachers and staff, the assistant can fetch live data (attendance, homework, fees, etc.) from the school's own database. Each tool is permission-checked — a parent only sees their own children.
5
Answer generation
The retrieved passages and tool results are wrapped in a secure data fence and sent to your AI provider. The system prompt instructs the assistant to cite only what it was given and never invent facts. All PII is stripped before anything leaves the server.
6
Output check
Every number, fee amount and date in the reply must exist in the cited passage. If a figure cannot be verified, the answer is discarded and replaced with a plain refusal. The user never sees an unverified answer.
7
Handoff check
After each reply, the message is checked against your handoff rules. If a rule fires (e.g. fee dispute, complaint, "talk to a person"), the conversation is routed to the inbox and the person is told honestly what is happening.

Setup checklist — do these in order

Before anything is live

A
Set the encryption key on the server
Your developer must set ASSISTANT_ENCRYPTION_KEY in the server environment before an AI provider key can be stored safely. Run python manage.py assistant_make_key to generate one. Without this, provider keys cannot be saved.
B
Add an AI provider
Go to Providers → Add provider. Choose OpenAI, Google Gemini, DeepSeek or a compatible server. You will need an API key from the provider. The key is encrypted and stored safely — it is never shown in full again, only its last 4 characters.

Supported providers:

OpenAI (GPT-4o, GPT-4o-mini)✓✓Pay-per-token
Google Gemini (1.5 Flash, 2.0)✓✓Pay-per-token
DeepSeek (V3, R1)✗✓Low cost
Any OpenAI-compatible serverVaries✓Varies
After adding a provider, use the Test connection button to verify the key works.
C
Set the monthly budget
In Settings → Money, set the Monthly budget (KSh) and the USD to KSh rate. The assistant refuses all calls if the budget is 0 or unset. Start with a small amount (e.g. KSh 500) while testing.
D
Add and approve knowledge documents
Go to Knowledge → Add document. You can upload PDFs, Word files, plain text, paste FAQ text, or add Q&A pairs directly.

Important: Documents must be in an Approved collection and their status set to Approved before the assistant can use them. Draft documents are never shown to users.

After approving, the background worker reads and embeds the document automatically. The document status changes to Ready when done. You must have python manage.py qcluster running.

Suggested starting documents:
  • Admission requirements and process
  • Fee structure (current term/year)
  • Term dates and school calendar
  • School rules and uniform policy
  • Portal how-to guide for parents
  • FAQ about the school
E
Set the safeguarding contact
In Settings → Safeguarding, enter the name, phone and email of your named safeguarding lead. This contact appears in every safeguarding reply and receives immediate alerts. Required before the signed-in assistant or student tutor can be switched on.
F
Approve the consent wording
In Settings → Public widget, read the consent text and tick the approval checkbox, then enter your name and today's date. The public widget will not appear on the website until this is done.
G
Test before going live
Use the Test console to ask questions and see exactly what the assistant retrieves and answers. Use the Answer desk to test as a specific role (Visitor, Parent, Student, Teacher). Both tools have their own daily limit and budget and do not count against the live assistant. The stop switch does NOT block them — only the console limits do.

Going live

1
Turn on the global switch
Settings → turn on Global switch (enabled). This alone does nothing — it is the master gate. The specific switches below control who can actually use the assistant.
2
Turn on the public widget (optional)
Turn on Public assistant then Website chat widget. The chat bubble will appear on all five public pages (Home, About, Academics, Gallery, Contact). Visitors can ask questions from approved public documents only.
3
Turn on the signed-in assistant (optional)
Turn on Signed-in assistant. Parents, students, teachers and staff get an "Ask the Assistant" link in their sidebar and a floating button on dashboard pages. They can ask about their own records (attendance, homework, fees, etc.).
4
Turn on student tutor mode (optional)
Turn on Student tutor mode. Students get a "Tutor mode" toggle in their assistant. The tutor guides with questions and hints rather than giving answers directly. It will not complete assessed work (quizzes, exams, homework marked as graded). Requires the signed-in switch and a safeguarding contact.
5
Set up handoff rules
Go to Handoff Rules → click Seed starter rules to add a Kenyan school starter set. Review the Safeguarding rule (marked Required — cannot be removed). Edit each rule's destination to point to the right person or team. This is how fee disputes, complaints and "talk to a person" requests are routed to your staff inbox.
{# ── Emergency stop ───────────────────────────────────────────────────────── #}

Emergency stop

If anything goes wrong, go to Settings and turn on the Stop switch. This immediately pauses everything — the public widget, the signed-in assistant, the answer desk, the test console and background document reading. In-flight calls are allowed to finish; no new calls start. It always wins over every other switch.

Turn the stop switch off again to resume. Nothing is lost — conversations, documents and settings are unchanged.

What each role can ask

Once the signed-in assistant is on, every signed-in user gets an "Ask the Assistant" link and a floating button. Answers use only that person's own records — a parent never sees another family's data, and a student never sees another student's.

RoleExample questionsWhat it can do
Parent "How is Amara's attendance?" · "When are fees next due?" · "Summarise her week" · "What is her timetable?" Attendance, homework due/overdue, released marks, fee balance and next due date, live classes, timetable, next lesson, week summary, school events, announcements — always about the child chosen in the child switcher. Tutor-usage counts for own children.
Student "What do I have due?" · "What is my next lesson?" · "Show me my class notes" Due work, progress summary, timetable, next lesson, class materials, upcoming live classes, points and badges, announcements. Tutor mode (when enabled) guides with hints and refuses graded work kindly.
Teacher "Who hasn't submitted homework?" · "What classes today?" · "How is the tutor used in my classes?" Unmarked work, unanswered class questions, today's classes, unfinished submissions (respects stream targeting), class progress, tutor-usage counts for own classes. Can request AI drafts (lesson outline, quiz questions in CSV import format, rubric, feedback) — always marked as drafts for review.
Director "How many students?" · "Attendance trend?" · "Is the community queue clear?" Read-only aggregates: school summary, 7-day attendance and engagement trends, community moderation backlog, unanswered class questions, handoff queue health.
Admin "What is the assistant spending?" · "Any documents waiting?" · "System health?" Everything the director gets, plus assistant usage/cost, knowledge gaps, pending document approvals, job failures and open safeguarding alerts. Can save an AI-drafted announcement as an unpublished draft for review.
Finance "Any announcements?" Announcements and approved knowledge documents only — no record tools.

Every live-data answer states when it was fetched (e.g. "Attendance as of today 09:10"). Users can opt into memory (language, tone, a short non-sensitive topic note) and delete it or their whole history at any time from the chat page's Personalisation panel.

Organising knowledge documents

Documents live in collections. A collection has an audience — Public, Signed-in, or restricted to specific roles or classes. A document can be narrower than its collection but never broader.

AudienceWho can see itUse for
PublicEveryone including website visitorsAdmissions, fees, term dates, school rules, FAQs
Signed-inAny logged-in user (parent, student, teacher, staff)Portal how-to guides, parent handbooks
Role-scopedOnly the specified rolesStaff policies (teacher + admin only), finance procedures
Class-scopedStudents and parents of specific classesSubject notes, class-specific timetables
Document status flow: Draft → Approved → (the background worker reads it) → Ready. Only Ready documents are searchable. Set a document to Archived to remove it from search immediately without deleting it.
{# ── Background worker ─────────────────────────────────────────────────────── #}

Background worker (qcluster)

The background worker must be running for documents to be read and embedded. Without it, approved documents stay in Waiting state and are never searchable.

Ask your developer to run this in a separate process:

python manage.py qcluster

In production this should run as a service (systemd, supervisor, or a Docker container). Check Failed jobs if documents are not being processed.
